The Adapter Pattern

Convert the interface of a class into another interface clients expect. Adapter lets classes work together that couldn't otherwise due to incompatible interfaces. Below are practical examples, gotchas, and modern alternatives.

Applicability

  • You have an existing class with an incompatible interface that you cannot change (often 3rd-party, legacy, or with lots of existing dependencies).
  • You want to create a middle-layer class that serves as a translator between your code and a legacy/3rd-party class.
  • You want to reuse several existing subclasses that lack some common functionality that can't be added to the superclass.
Note: The overall complexity increases because you need to introduce new interfaces and classes. Sometimes it's simpler just to change the service class.

Checklist

  • At least two incompatible interfaces
  • Service class reference in adapter
  • Adapter implements client interface
  • Delegates work to service
  • Handle format conversion

Practical Example: Power Plug Adapter

A real‑world analogy: A traveler needs an adapter to use their US power plug in a European socket. The adapter has an American outlet and a European plug, translating between the two standards.

Java — Object Adapter (Composition)

// Target interface (expected by client)
interface StandardPlug {
    void powerUp();
}

// Existing service (adaptee) with incompatible interface
class EuropeanSocket {
    public void connectEU() {
        System.out.println("Powered via EU socket");
    }
}

// Adapter: wraps EU socket to look like StandardPlug
class PlugAdapter implements StandardPlug {
    private EuropeanSocket europeanSocket;

    public PlugAdapter(EuropeanSocket socket) {
        this.europeanSocket = socket;
    }

    @Override
    public void powerUp() {
        // Translate from expected interface to actual service
        europeanSocket.connectEU();
    }
}

// Usage
StandardPlug adapter = new PlugAdapter(new EuropeanSocket());
adapter.powerUp();  // "Powered via EU socket"

JavaScript — Object Adapter

// Target interface (duck typing)
class StandardPlug {
    powerUp() {
        throw new Error('Must be implemented');
    }
}

// Existing service
class EuropeanSocket {
    connectEU() {
        console.log('Powered via EU socket');
    }
}

// Adapter: wraps EuropeanSocket
class PlugAdapter extends StandardPlug {
    constructor(socket) {
        super();
        this.socket = socket;
    }

    powerUp() {
        // Translate to actual service method
        this.socket.connectEU();
    }
}

// Usage
const adapter = new PlugAdapter(new EuropeanSocket());
adapter.powerUp();  // "Powered via EU socket"

Python — Object Adapter

from abc import ABC, abstractmethod

# Target interface
class StandardPlug(ABC):
    @abstractmethod
    def power_up(self):
        pass

# Existing service (incompatible)
class EuropeanSocket:
    def connect_eu(self):
        print("Powered via EU socket")

# Adapter: implements target, wraps service
class PlugAdapter(StandardPlug):
    def __init__(self, socket: EuropeanSocket):
        self._socket = socket

    def power_up(self):
        # Translate to actual service
        self._socket.connect_eu()

# Usage
adapter = PlugAdapter(EuropeanSocket())
adapter.power_up()  # "Powered via EU socket"

Real‑World Scenario: Analytics Integration

You're building a stock market monitoring app that downloads XML data from multiple sources. You decide to integrate a 3rd-party analytics library, but it only accepts JSON. The solution: create an XML‑to‑JSON adapter.

// Existing app works with XML
class StockDataFeed {
    String getStockData() { return "<stock>...</stock>"; }
}

// 3rd-party library wants JSON (you can't modify it)
interface AnalyticsService {
    void analyze(String jsonData);
}

// Adapter: bridge the gap
class XMLtoJSONAdapter implements AnalyticsService {
    private StockDataFeed feed;
    public XMLtoJSONAdapter(StockDataFeed feed) { this.feed = feed; }

    @Override
    public void analyze(String xmlData) {
        String json = convertXMLtoJSON(feed.getStockData());
        // Now pass JSON to actual analytics (if we had it)
    }

    private String convertXMLtoJSON(String xml) {
        // conversion logic
        return "{ \"stocks\": [...] }";
    }
}

✅ Benefits

  • Single Responsibility: Interface conversion code is separated from business logic.
  • Open/Closed Principle: Add new adapters without modifying client code.
  • Loose Coupling: Clients depend on abstractions, not concrete incompatible classes.

⚠️ Drawbacks

  • Overall Complexity: Introduces new interfaces and classes; sometimes simpler to just modify the service.
  • Performance Overhead: Extra layer of indirection (usually negligible).
  • Harder to Trace: Deeper call stack makes debugging less transparent.

Implementation Steps

  1. Make sure you have at least two classes with incompatible interfaces (a useful service class you can't change, and one or several client classes that would benefit from it).
  2. Declare the client interface and describe how clients communicate with the service.
  3. Create the adapter class and make it follow the client interface. Leave methods empty initially.
  4. Add a field to store a reference to the service object (usually initialized via constructor).
  5. Implement all methods of the client interface, delegating real work to the service and handling format/interface conversion.
  6. Clients should use the adapter via the client interface, allowing you to change or extend adapters without breaking client code.

Relations with Other Patterns

  • Bridge: Usually designed up-front; Adapter is commonly used with an existing app to make incompatible classes work together.
  • Decorator: Provides a different interface (Adapter) vs. extended same interface (Decorator). Decorator supports recursive composition; Adapter doesn't.
  • Proxy: With Proxy, the interface stays the same. With Adapter, you access via a different interface.
  • Facade: Defines a new interface for existing objects; Adapter tries to make existing interface usable. Facade works with subsystems; Adapter wraps one object.
